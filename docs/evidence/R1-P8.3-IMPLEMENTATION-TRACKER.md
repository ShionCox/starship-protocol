# R1 P8.3 实施跟踪

> 这是 P8.3 的实施记录，不等同于 R1 完成清单。Creator 持久资源和 Web 人工验收完成前，不勾选 P8.3 主项。

## 目标

- 运行时只消费 `assets/config/csv/` 九张 CSV；`editor-prefabs.csv` 只负责编辑器定义到 Prefab 的白名单映射。
- 房间、船员、船体页面使用 CSV 草稿、150ms 防抖预览、保存/取消和实例一次 Undo。
- 通过 Creator 公共 Asset DB/Scene API 非破坏式创建/更新共享 Prefab、三场景和标准新手船。
- 清除旧 JsonAsset 属性覆盖、旧 `hullCells` 引用和失效的 `CrewMember.prefab`。

## 已实现（自动验证）

- `hulls.csv.cellMask` 使用 `V/B/W` 与 `/` 行分隔，运行时保留 `HullDefinition.cellTypes`；旧 `hull-cells.csv` 已从代码链移除。
- 视觉 CSV 增加显示缩放与网格偏移字段，帧矩形、边界、FPS、视觉类型和跨表引用严格校验。
- 编辑器 Prefab 映射由 `editor-prefabs.csv` 驱动，不再维护 `SHARED_CSV_BINDINGS` 硬编码目录。
- 房间 CSV 草稿支持实时预览、连接器校验、保存/reimport/全量回滚、取消恢复和实例白名单编辑。
- 房间、船员、船体支持新建草稿、追加/覆盖行和取消草稿；船员页可编辑稀有度、外观标识、词条和 SOLDIER 职业。
- 定义预览清理只调用 `RoomView`、`CrewView`、`ShipView` 白名单方法，不保存 Scene、不创建 Undo。
- 三场景创建/更新分支按固定顺序补齐九表绑定、房间/船员外观、ShipView 实例和场景引用；有效手工布局与视觉替换保持不变，冲突在写入前停止。
- 场景回滚路径不再调用未配对的 `snapshotAbort`；录制失败先取消 recording，再删除临时节点。
- 配置版本固定为 `r1-p8-close-1`，旧开发快照不迁移。
- 房间/船员/船体旧 JSON 创建、发现、编辑源码、面板、消息和测试已删除；PSS 来源 JSON、存档和布局 JSON 仍属于非配置用途。
- 配置表页保持只读审计；“批量导入并校验”通过 Creator 公开原生文件选择器一次读取完整编辑器 bundle，先全量校验再原子保存。
- 主场景和战斗场景的 `画布` 位于 `1280×720` 设计画面的中心 `(640,360)`，其子节点 `世界根` 局部位置固定为 `(0,0)`；ShipView 只保留相对位置，UIRoot 不随世界层偏移。
- 九张 CSV 引用已集中到 Main/Battle“应用根”的唯一 `GameConfigCsvSource`；场景 ShipView 显式同源，Room/Crew 从所属 ShipView 读取。领域 Prefab 只保存稳定 ID 与代表性外观，打开时由创作工具注入现有白名单 DTO。
- 删除逐领域 Prefab 九表写入循环；ShipView/UIRoot 结构升级分别收敛为一次打开、一次保存。资源操作改用 `imported/invalid` 状态与 650ms 剩余静默窗口，热缓存就绪时不固定休眠；重建结果输出各阶段和总耗时。

以下为 2026-08-14 历史故障及修复记录，不代表当前仍在复现。首次 Creator 重建复验发现：扩展首次打开存在消息注册竞态、Prefab 快速切换会输出
`UNKNOWN ... open LaserRoom.prefab`、半绑定 CSV 会产生瞬态警告，且 Battle 编辑态 `start()` 会误报运行时引用错误。
本轮已改为轻量消息入口、通过 Asset DB 将 `db://` URL 解析为 UUID 后再打开资源、统一稳定等待/重试、
拒绝空资源查询、半绑定预览静默、Battle 仅在运行预览执行 `start()`，并要求 BattleScene 切走重开后
再次验证持久引用；因此必须重新执行下面的 Creator 验收，
旧绿色“重建完成”截图不作为通过证据。

第二次 Creator 复验已消除 Prefab `UNKNOWN open`，但仍在 `<process:scene>` 留下一条
`query-asset-info parameter error`。本机 Creator 3.8.8 声明 `.scene` 应使用
`Editor.Message.request('scene', 'open-scene', sceneUuid)`；现已把 Boot/Main/Battle 从通用
Asset DB `open-asset` 分离到专用 Scene UUID 接口，下一次复验只接受零红错结果。

第三次 Creator 复验把残余错误定位为 Prefab 导入竞态：`MedicCrew` 与 `SoldierCrew` 在
`save-scene` 后被扩展再次强制 `reimport`，MainScene 随即读取其 `import://` JSON 时先返回
`status: 0`，约 6～10 秒后相同资源又返回 200；紧随其后的 `query-asset-info parameter error`
属于该失败的级联结果。现已删除房间/船员 Prefab 的重复 `reimport`，改为只轮询 Creator
公开 `AssetInfo.imported/invalid` 状态；CSV、SpriteAtlas 与 AnimationClip 等文本资源仍保留
必要的重导入。Scene 切换同时要求目标场景名和 Bootstrap 都匹配，不能再用旧场景树误判成功。

第四次 Creator 复验提供了完整保存错误：BootScene、ShieldRoom 和 MainScene 均在
`asset-db/save-asset` 阶段遇到文件占用；MainScene 从报错到重新导入完成实测约 541ms，
而旧保存重试间隔只有 500ms，导致第二次保存再次撞锁。现已由公共打开入口记录当前
Scene/Prefab，公共 `saveAuthoringScene` 在保存前后都等待该资源导入稳定。当前屏障以
`AssetInfo.imported/invalid` 和最后一次打开、保存或 `asset-change` 的 650ms 静默窗口为准，
只等待剩余时间；瞬态重试间隔为 1000ms，全部房间、船员和三场景不再维护领域级等待链。
