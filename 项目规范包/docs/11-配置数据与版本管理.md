### R1 P8 CSV 配置

R1 P8 起唯一创作与开发输入是 `assets/config/csv/` 下九张运行时 CSV：

```text
game.csv, hulls.csv, rooms.csv, connector-ports.csv, floors.csv,
crews.csv, crew-traits.csv, visuals.csv, visual-frames.csv
```

编辑器另维护不进入运行时的 `editor-prefabs.csv`，用稳定 `definitionId` 白名单映射到 Prefab。每张表第一行是稳定英文表头，第二行是以 `#稳定标识` 开头的中文说明，第三行起才是数据；整批读取必须同时校验 BOM/CRLF、RFC4180、稳定 ID、数值、Mask 和跨表引用。

- `id` 使用各领域约定的稳定 kebab-case 字符串；Prefab 不复制规则数值。
- `hulls.csv.cellMask` 使用 `/` 分行、`V/B/W` 分别表示 VOID/BUILDABLE/FIXED_WALL，尺寸必须与 `gridWidth/gridHeight` 完全一致。
- `visuals.csv` 与 `visual-frames.csv` 保存资源路径、显式帧矩形、播放模式、帧率和脚底锚点；manifest 只承担来源 Hash 与授权审计。
- GameCore 通过唯一 CSV 解析入口生成 `GameConfigCatalog`；Cocos 组件只消费已验证定义，不读取 JsonAsset 或插件目录。
- 编辑器保存始终重新读取九张运行时表及 `editor-prefabs.csv`，全量校验后原子写入并 reimport；失败按已写入表逆序回滚。

### 正式 Windows 配置包

以下内容是未来 R2 验收要求，当前仓库没有 Launcher、Native 解密桥、发布工具或服务器实现，不能宣称已完成：

- `assets/config/csv/**` 的 CSV 是 R1 创作与开发输入，不是正式客户端直接读取的交付格式。
- 发布工具将通过 Schema/逻辑校验的配置规范化后打包为 AES-256-GCM 认证加密包；每个包必须记录 `schemaVersion`、`buildId`、`configVersion`、`keyId`、随机 12 字节 IV 和 16 字节认证标签。
- AES 内容密钥由 Secret/KMS 生成和轮换，不提交仓库、不写入签名清单、不固定编译进 TypeScript。
- 加密配置包的 SHA-256 进入 RSA-PSS 签名文件清单，并按 `CORE` 文件每次启动完整校验。
- 客户端通过短时 Launch Ticket 与玩家会话取得当前版本的配置描述和内容密钥；密钥只保存在进程内存。
- 启动器把已验签清单中的 Build/Config/Ticket URL、稳定安装 ID 和短时 Ticket 传给游戏进程；Cocos 通过公开 Native Plugin 读取上下文，依次请求 Guest Session、Bootstrap 和 `.spcfg`，校验 SHA-256 后才认证解密并原子替换唯一 `ConfigRegistry`。
- 正式 Native 任一步失败都必须停止初始化，不得回退到 Prefab 绑定的旧 JsonAsset；编辑器和 Web 原型仍可读取已校验 CSV 做可视化创作与非正式预览。
- 正式 Windows 构建必须启用 Creator Native `Encrypt JS`、关闭 Source Map，并审计 `.jsc`、脚本备份、私钥材料和明文规则；R0/R1 Web 预览允许明文 CSV，但必须标记为非正式发行。
- 配置保密和文件完整性不替代服务端权威。服务端仍按自身 `configVersion` 校验所有影响账号、经济和战斗的 Command。

实现与密钥边界见 `ADR-0002-Windows正式发行与服务端版本验证.md`。

## 补充：单一配置入口原则

- 同一种配置只允许一个正式 Registry/Repository。
- 客户端、服务端、战斗服务使用相同稳定 ID。
- 业务代码禁止到处直接读取零散 CSV；统一通过配置访问层。
- 配置字段变更必须考虑旧存档和旧 Replay。
- 编辑器插件可以创建配置，但运行时配置访问层和 GameCore 不得依赖插件代码。
- R2 正式运行时的加密配置访问层将在真实发布阶段重新实现；它必须原子替换 `GameConfigCatalog`，并与当前 buildId/configVersion 匹配。View 不得直接读取零散 JsonAsset。
