### 房间定义 JSON

R0 起房间规则使用 `assets/config/rooms/<room-id>.json`，至少包含：

```text
schemaVersion, id, displayName, category,
width, height, maxLevel, maxHp,
minPower, maxPower, powerGeneration, crewCapacity
```

- `id` 使用 `room-` 开头的小写 kebab-case 稳定字符串。
- `powerGeneration` 是 R1 能源房间的基础产能；旧 schema 1 文档缺失时按 0 兼容，新增能源房间应显式填写。
- JSON 是房间规则唯一来源；Prefab 不再复制宽高和数值规则。
- JsonAsset 由 Cocos 适配层读取，再交给纯 TypeScript 解析器校验。
- 插件表单只能生成当前支持的 `schemaVersion`，不能静默升级旧配置。
- 编辑器插件通过 Asset DB 真实依赖把 JSON 与 Prefab 配对；创建成功后自动绑定 JsonAsset，运行时不依赖插件代码，也不维护第二份房间目录。

### 船体定义 JSON

R1 船体规则使用 `assets/config/hulls/<hull-id>.json`，包含 `schemaVersion`、稳定 ID、中文名称、等级、网格宽高、0/1 Mask、船员/房间上限和 `visualId`。Mask 长度必须等于宽×高。

开发期唯一 `GameConfigCatalog` 只保存已经通过纯 TypeScript 解析器校验的 Hull、Room 和 Crew 定义；业务代码不得绕过目录自行读取零散规则。

### 正式 Windows 配置包

以下内容是未来 R2 验收要求，当前仓库没有 Launcher、Native 解密桥、发布工具或服务器实现，不能宣称已完成：

- `assets/config/**` 的 JSON 是创作与发布输入，不是正式客户端直接读取的交付格式。
- 发布工具将通过 Schema/逻辑校验的配置规范化后打包为 AES-256-GCM 认证加密包；每个包必须记录 `schemaVersion`、`buildId`、`configVersion`、`keyId`、随机 12 字节 IV 和 16 字节认证标签。
- AES 内容密钥由 Secret/KMS 生成和轮换，不提交仓库、不写入签名清单、不固定编译进 TypeScript。
- 加密配置包的 SHA-256 进入 RSA-PSS 签名文件清单，并按 `CORE` 文件每次启动完整校验。
- 客户端通过短时 Launch Ticket 与玩家会话取得当前版本的配置描述和内容密钥；密钥只保存在进程内存。
- 启动器把已验签清单中的 Build/Config/Ticket URL、稳定安装 ID 和短时 Ticket 传给游戏进程；Cocos 通过公开 Native Plugin 读取上下文，依次请求 Guest Session、Bootstrap 和 `.spcfg`，校验 SHA-256 后才认证解密并原子替换唯一 `ConfigRegistry`。
- 正式 Native 任一步失败都必须停止初始化，不得回退到 Prefab 绑定的源 JsonAsset；编辑器和 Web 原型仍可读取 JsonAsset 做可视化创作与非正式预览。
- 房间 JsonAsset Inspector 引用必须标记为编辑器专用；若 Creator 依赖收集仍把源文档带入 Native 生成目录，构建工具只能定向清理生成产物，禁止改写 Scene、Prefab 或 meta 源文件。
- 正式 Windows 构建必须启用 Creator Native `Encrypt JS`、关闭 Source Map，并审计 `.jsc`、脚本备份、私钥材料和明文规则；R0/R1 Web 预览允许明文 JSON，但必须标记为非正式发行。
- 配置保密和文件完整性不替代服务端权威。服务端仍按自身 `configVersion` 校验所有影响账号、经济和战斗的 Command。

实现与密钥边界见 `ADR-0002-Windows正式发行与服务端版本验证.md`。

## 补充：单一配置入口原则

- 同一种配置只允许一个正式 Registry/Repository。
- 客户端、服务端、战斗服务使用相同稳定 ID。
- 业务代码禁止到处直接读取零散 JSON；统一通过配置访问层。
- 配置字段变更必须考虑旧存档和旧 Replay。
- 编辑器插件可以创建配置，但运行时配置访问层和 GameCore 不得依赖插件代码。
- R2 正式运行时的加密配置访问层将在真实发布阶段重新实现；它必须原子替换 `GameConfigCatalog`，并与当前 buildId/configVersion 匹配。View 不得直接读取零散 JsonAsset。
