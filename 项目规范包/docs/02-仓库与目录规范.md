### Cocos 外部模块注意事项

Cocos Creator 3.8 支持 ESM 和 npm 外部模块，但客户端共享包必须：

- 使用 ESM；
- 不依赖 Node.js 内置模块；
- 不依赖 DOM；
- 不依赖浏览器专有 API；
- 不使用 Cocos 不支持的 TypeScript 特性；
- 避免 CommonJS/ESM 混用。

如果早期本地 workspace 导入影响开发效率，R0 可暂时将 GameCore 放到：

```text
client-cocos/assets/scripts/game-core/
```

但必须保持“纯 TS、零 `cc` 引用”，进入 R2 权威战斗服务前再抽取为共享 package。

## 6.A 目录职责规范

> 下列目录职责是强约束。新增目录前先确认是否已有归属，避免同一职责出现两套实现。

```text
spaceship-game/
├─ client-cocos/                     # Cocos Creator 客户端工程
│  ├─ assets/
│  │  ├─ scenes/                     # 少量主场景；不放业务逻辑
│  │  ├─ prefabs/                    # 可复用 Prefab；按业务域分类
│  │  ├─ config/                     # 客户端版本化配置 JSON；按业务域分类
│  │  ├─ bundles/                    # Asset Bundle 入口与分包资源
│  │  ├─ textures/                   # 图片、图集源资源
│  │  ├─ audio/                      # 音乐、音效
│  │  ├─ fonts/                      # 字体及字库
│  │  └─ scripts/
│  │     ├─ bootstrap/               # 启动、初始化、环境装配
│  │     ├─ application/             # 用例编排；连接 UI 与领域逻辑
│  │     ├─ presentation/            # ShipView/RoomView/CrewView 等表现层
│  │     ├─ ui/                      # 页面、弹窗、通用 UI 组件
│  │     ├─ input/                   # 输入映射，不直接写游戏规则
│  │     ├─ network/                 # HTTP/WebSocket 客户端适配
│  │     ├─ services/                # 客户端运行时服务
│  │     ├─ adapters/                # Cocos 与纯 TS 核心之间适配器
│  │     └─ debug/                   # 仅调试环境使用的可视化工具
│  └─ settings/                      # Cocos 项目设置，必须版本控制
│  └─ extensions/                    # 项目级 Cocos 编辑器扩展；不得进入运行时依赖
│
├─ packages/
│  ├─ game-core/                     # 纯 TS 游戏规则；禁止依赖 cc
│  ├─ game-schema/                   # 跨端共享数据结构
│  ├─ game-protocol/                 # API / Battle / Replay 协议
│  └─ seeded-rng/                    # 唯一确定性随机入口
│
├─ services/
│  ├─ api/                           # FastAPI 业务服务
│  └─ battle/                        # Node.js 权威战斗服务
├─ native/
│  └─ launcher/                      # C++/Win32 签名启动入口与文件验证
│
├─ apps/
│  └─ admin-web/                     # Vue 3 运营后台
│
├─ tools/
│  ├─ config-validator/              # 配置静态校验
│  ├─ battle-simulator/              # 无画面批量战斗模拟
│  └─ replay-inspector/              # Replay 检查工具
│  └─ release-security/              # 仅发布环境使用的加密/签名工具
│
├─ docs/                             # 项目文档唯一事实源
├─ templates/                        # 文档/设计模板
├─ AGENTS.md                         # AI/开发代理强规则
└─ README.md                         # 总览与导航，不堆业务细节
```

## 6.B 文件命名规范

- TypeScript 类/组件文件：`PascalCase.ts`，例如 `ShipGridModel.ts`。
- 纯函数/小工具：`camelCase.ts` 或以职责命名，例如 `calculateDamage.ts`。
- Cocos Component 类名与文件名保持一致。
- Prefab：`PascalCase.prefab`。
- Scene：`PascalCase.scene`。
- 配置文件：`kebab-case.json`。
- 文档：`NN-中文主题.md`。
- 禁止出现 `common2.ts`、`utils_new.ts`、`temp-final.ts` 等不可维护名称。

## 6.C 依赖方向

```text
Cocos View / UI
      ↓
Application / Adapter
      ↓
GameCore
      ↓
Schema / Shared Utility
```

禁止反向依赖：

- GameCore → Cocos；
- GameCore → UI；
- Schema → Service；
- 配置模型 → 网络实现。

## 6.D 目录创建原则

新增目录必须回答三个问题：

1. 现有目录为什么不能容纳？
2. 该目录的唯一职责是什么？
3. 谁可以依赖它、它可以依赖谁？

无法回答时不创建新目录。

## 6.E 当前 Cocos 工程的创作工具目录

R0 根目录仍是 Cocos 工程，不提前迁移 monorepo。当前使用：

```text
assets/config/rooms/                 # 版本化房间规则 JSON
assets/prefabs/                      # 房间等表现 Prefab
extensions/starship-editor-tools/    # 唯一项目编辑器扩展宿主
```

`starship-editor-tools` 内部按领域拆分源码，但只有实际实现的领域才能注册资源菜单或创作面板区域。NPC、关卡尚未开发时不创建空面板、空 Service 或空 Registry。

房间模块的编辑器职责固定为：`rooms/` 发现 JSON-Prefab 依赖、资源事务、Prefab 绑定校验和场景实例；`scene/` 只负责标准场景骨架；`panels/` 负责唯一创作面板的状态展示和操作。插件可以依赖公开 Asset DB/Scene/Selection 消息，运行时资产和 GameCore 不得依赖插件。
