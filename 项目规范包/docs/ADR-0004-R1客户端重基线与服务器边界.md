# ADR-0004：R1 客户端重基线、场景复用与服务器边界

- 状态：接受
- 日期：2026-08-12
- 影响范围：R1 客户端、场景、UI、飞船聚合、开发存档、创作插件、未来服务端

## 背景

R0 已证明网格、房间、镜头与 Web Desktop 技术路线；R1 已完成能源和单层船员移动纵切。继续把玩法、UI 和本地存档绑定在 `PrototypeScene` 会让主菜单、不同船体、敌我双舰和未来服务端状态难以扩展，也会保留大量只服务一次性验收的运行时兜底。

项目仍在开发阶段，开发存档没有兼容价值，因此选择直接删除 Prototype 兼容链和三个旧 Key，不设计迁移层。

## 决策

1. 运行场景固定为 `BootScene`、`MainScene`、`BattleScene`。主菜单、星图、飞船、建造、船员与设置都是 `MainScene` 内 Page Prefab；战斗才切换 `BattleScene`。
2. `MainScene` 与 `BattleScene` 实例化同一份 `UIRoot.prefab`。UIRoot 只承载 HUD、页面、弹窗、提示和加载层，不承载飞船世界节点。
3. 一种船体不是一个 Scene。船体由 `HullDefinition`、外观 Prefab 与 `ShipSnapshot` 组成；Main/Battle 都复用 `ShipView.prefab`。
4. `ShipGridModel` 的网格尺寸、Mask 和容量只来自 `HullDefinition`。定义 ID 与实例 ID 分离；跨模型 Command 必须携带 `shipId`。
5. `ShipModel` 是单舰聚合根，统一布局、能源、导航、船员和原子快照。布局改变只重建所属飞船的导航图。
6. UI 和 View 只依赖 `PlayerStatePort` 的状态与 Command 结果，不直接读取浏览器存储。开发期实现只使用 `starship-protocol:dev:player-state:v1` 一个 Key，写入完整玩家状态 Envelope；旧 Key 不读取、不迁移。
7. Bootstrap 只连接 Creator 已持久保存的节点、组件、Prefab 和 JSON 引用。缺少依赖时用中文错误停止，禁止运行时补节点、组件、房间或 UI。
8. 创作插件只保留可重复使用的房间、船员、船体、飞船与场景骨架能力；删除 R1 一次性模板替换和兼容入口。插件 `dist` 是构建产物，不由 Git 跟踪。
9. R2 Launcher、Native 配置桥、FastAPI 发布安全样例和发布工具本轮移除。ADR-0002、威胁边界和验收要求继续作为未来正式发行约束，但不再宣称已有可执行实现。
10. 未来联网状态沿用 `requestId + idempotencyKey + expectedRevision + configVersion` 契约。资源、计时和奖励以服务端时间与事务为权威；客户端不提交收益数值。
11. 离线建造、升级和研究按完整真实离线时间推进；离线资源产出最多结算 12 小时并自动入账。离线期间不运行战斗、任务胜负、船员移动、AI 或随机掉落。
12. 首版联网 Command 响应固定返回完整权威 State，不提前支持 Delta；玩家 Bootstrap 在本次请求完成离线结算时返回可选 `OfflineSettlementSummary`。
13. R1 Web Desktop 使用 Creator 内置 `main` Bundle、BattleScene 预加载和场景资源自动释放；Web Desktop 不要求小游戏平台的初始场景分包。只有动态资源或包体出现实际拆分需求时才启用自定义 Bundle。

## 结果与取舍

- 优点：场景数量稳定；新船体不复制 Scene；敌我双舰复用同一 View；UI 与存储/网络解耦；开发数据可以直接重置；未来服务端接入不需要改页面调用模型。
- 代价：现有 Prototype 场景和开发存档作废；三套正式 Scene/共享 Prefab 必须在 Creator 中重新搭建并重新做 Web 验收。
- 不做：不提前实现账号、经济、离线结算进程、Redis、Battle Service、商城、邮件或完整通用 UI 组件库。

## 迁移顺序

1. 冻结 R0 证据并建立 `R1-FOUNDATION-CHECKLIST.md`。
2. 完成 `HullDefinition → ShipModel → PlayerStatePort` 纯 TypeScript 重基线。
3. 在 Creator 中持久创建 Boot/Main/Battle、ShipView 和共享 UIRoot；通过后删除 PrototypeScene。
4. 收敛创作插件并完成船体/飞船创作。
5. 重新完成 Web Desktop 构建、场景切换、双舰隔离、能源/船员与本地恢复验收。
