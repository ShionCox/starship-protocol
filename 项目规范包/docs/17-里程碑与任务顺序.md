### M0-007 创作工具增强（不新增 R0 编号）

- 资源管理器菜单创建 JSON + Prefab，失败可回滚；
- 真实依赖自动发现有效房间，非法或多重绑定不进入列表；
- 项目/Panel 菜单打开可停靠“星舰创作工具”，在面板中初始化标准 Prototype 场景骨架；
- 面板按层级选择上下文显示自动发现的房间建筑，按 GameCore 首个合法空位创建实例；
- 禁止依赖 Cocos 3.8.8 私有层级右键入口；面板隐藏/关闭时停止 Selection 轮询；
- 自动测试通过后，必须再取得 Cocos 菜单、骨架、实例、自动绑定和 Undo/Redo 截图，才可在完成清单中勾选新增增强证据。

## R2-SEC Windows 正式发行安全前置

R1 完整闭环通过后、对外发布 Windows 正式客户端前，按以下顺序完成：

当前仓库只保留决策和验收要求，以下项目全部未开始：

1. `R2-SEC-001`：复核 Windows 正式发行 ADR、威胁模型和 Web 非正式定位；
2. `R2-SEC-002`：在真实发布流水线实现 AES-GCM 配置包、RSA-PSS 清单和目录复验；
3. `R2-SEC-003`：实现独立 Win32 启动器的 Authenticode、HTTPS、验签、Hash 和离线冷启动；
4. `R2-SEC-004`：实现真实 FastAPI Manifest、Launch Ticket、Session 和 Bootstrap；
5. `R2-SEC-005`：实现 Native 配置桥并原子更新 GameConfigCatalog，移除源 JsonAsset 正式运行依赖；
6. `R2-SEC-006`：完成真实 HTTPS Bootstrap/CDN/Ticket 正向链路；
7. `R2-SEC-007`：启用 Windows Release 脚本加密并审计 staging 无 source map/明文规则；
8. `R2-SEC-008`：部署 Secret/KMS、TLS、Redis Rate Limit、审计和密钥轮换；
9. `R2-SEC-009`：完成 Authenticode 与签名安装器；
10. `R2-SEC-010`：全新安装、篡改、断网、版本拒绝、轮换和服务端权威端到端验收。

完成状态与证据以根目录 `R2-SECURITY-CHECKLIST.md` 为准。不得用“客户端已加密”替代服务端业务权威。

# 54. 项目风险

## 54.1 最大风险：需求爆炸

参考产品已长期运营多年，不能首版复制所有内容。

解决：严格执行 `R0 → R1 → R2 → R3` 版本门槛。

## 54.2 最大技术风险：战斗逻辑与渲染耦合

解决：Pure TS GameCore + Cocos View。

## 54.3 最大联网风险：客户端权威

解决：Node Battle Service。

## 54.4 最大长期风险：配置升级导致旧回放失效

解决：`battleRuleVersion + configVersion + Replay Version`。

## 54.5 最大 AI 风险：规则组合爆炸

解决：白名单 DSL、Rule Validator、Priority、AI Debugger、Fuzz Test、最大规则数限制。

## 54.6 最大正式发行风险：把客户端加密误当成不可作弊

解决：Windows 签名启动器与 AES-GCM 只负责发布完整性和提高静态修改成本；账号、库存、奖励、布局和战斗结果仍由 FastAPI/Node Battle Service 权威校验。
