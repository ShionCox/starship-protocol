# ADR-0002：Windows 正式发行与服务端版本验证

- 状态：接受
- 日期：2026-08-09
- 影响范围：正式客户端平台、构建发布、配置分发、启动器、FastAPI、安全验收

## 背景

Web 与本地客户端都运行在玩家控制的设备上。把 JSON 改名、压缩或只在客户端内置对称密钥，不能阻止主动修改；最多提高读取成本。真正影响账号、奖励、库存和战斗结果的数据必须由服务端权威校验。

项目仍需要防止普通玩家直接替换客户端规则、脚本或资源，因此正式发行需要在 Cocos 游戏进程之前建立独立的版本与文件信任链，同时明确客户端防护不是服务端反作弊的替代品。

## 候选方案

### 方案 A：继续正式发布 Web Desktop，仅混淆/压缩资源

优点：发布简单，R0 已验证。

缺点：浏览器资源与执行环境完全由玩家控制，无法安全保存验证密钥，也无法对启动入口建立系统级代码签名信任。

### 方案 B：Windows Native + 签名启动器 + 服务端权威

优点：可使用 Authenticode、WinHTTP、WinTrust、BCrypt、Cocos Native 脚本加密、签名清单和安装器；服务端仍掌握最终业务权威。

缺点：需要 Windows 构建链、代码签名证书、Secret/KMS、HTTPS 发布服务和额外验收。

### 方案 C：强制始终在线并把所有规则都放服务端

优点：客户端静态规则最少。

缺点：破坏离线冷启动与弱网体验；表现所需数据仍需缓存；不能消除客户端运行时被观察或修改的可能。

## 决策

选择方案 B，并锁定以下规则：

1. 正式客户端为 Cocos Creator 3.8.8 Windows Native；Web Desktop 只用于 R0/R1 开发预览和自动化验证，不作为正式商业发行入口。
2. 游戏通过独立 Win32 启动器启动。启动器先验证自身 Authenticode，再通过 HTTPS 请求最新签名文件清单。
3. 发布清单使用 RSA-PSS-SHA256；私钥只存在于离线签名环境或 KMS/HSM，启动器只嵌入公钥。
4. `.exe`、`.dll`、Cocos 加密脚本和加密规则包属于核心文件，每次启动完整 SHA-256；普通资源可在同一签名 Build 下按大小、修改时间和上次 Hash 增量校验。
5. 任何签名、路径、大小或 Hash 不一致都禁止启动；客户端不自动修复，提示玩家从正式渠道重新安装。
6. 网络不可用时，只允许使用本机上一次已经验签并完整通过的清单冷启动，游戏进入离线/连接页；服务端明确拒绝版本时不得降级为离线绕过。
7. 规则配置由发布工具打包为 AES-256-GCM 认证加密包；密钥由服务端在短时 Launch Ticket 与玩家会话都通过后经 HTTPS 下发，仅保留在进程内存。
8. Cocos Native 正式构建启用引擎脚本加密；这属于提高逆向成本，不作为业务安全边界。
9. FastAPI 负责版本清单、Launch Ticket、玩家会话、配置 Bootstrap 和业务编排；Node Battle Service 负责权威战斗。客户端提交的奖励、库存、胜负和配置数值一律不可信。
10. 插件、R0 创作 JSON 和 Web 预览不得进入正式发布信任链；正式发布必须通过“无明文规则依赖”审计。

## 原因

该方案把不同问题放到正确层级：Windows 系统 API 建立文件与发布方信任，AES-GCM 防止静态配置直接阅读和无痕修改，服务端权威防止玩家通过替换或补丁客户端获得真实业务收益。它不承诺在玩家完全控制的机器上实现绝对不可逆向，而是采用商业游戏可执行、可轮换、可审计的分层防护。

## 影响

- 代码：新增 `native/launcher/`、`tools/release-security/` 和 `services/api/` 发布安全切片；后续新增 Cocos Native 配置桥接与 Node Battle Service。
- 数据：正式规则包使用 AES-256-GCM；源 JSON 继续作为创作事实源，但不得直接进入正式运行时依赖。
- Replay：Replay 继续记录 `configVersion`、`battleRuleVersion` 和最终 Hash，由权威服务生成或复核。
- 性能：核心文件每次完整 Hash；普通资源使用签名 Build 范围内的增量缓存。
- 部署：需要 TLS、Secret/KMS、RSA 签名密钥、AES 内容密钥、Windows 代码签名证书、签名安装器和回滚清单。
- Cocos 编辑器搭建与 Inspector：R0/R1 创作流程保持可视化；编辑器插件不参与运行时安全。

## 迁移方案

1. R0/R1 继续完成 Web 技术验证，不把明文预览包对外正式发行。
2. R2 前置阶段完成发布工具、原生启动器和 FastAPI 发布安全接口。
3. 将 Cocos 正式运行时从 `JsonAsset` 直接读取迁移到单一 `ConfigRegistry`，接入 Native AES-GCM 解密桥；编辑器预览继续读取源 JSON。
4. 启用 Cocos Windows Release 脚本加密，生成 staging 目录，加入加密规则包与已签名启动器。
5. 清单签名、离线复验、篡改拒绝、断网冷启动和 Authenticode 全链路通过后，才允许生成正式安装器。
