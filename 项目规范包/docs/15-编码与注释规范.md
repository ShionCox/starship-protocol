# Cocos / TypeScript 编码与中文注释规范

> **文档规则**：本文件是该主题的唯一主文档；其他文档如需使用本主题规则，应通过链接引用，不复制整段内容。  
> **中文注释**：涉及关键数据结构、算法、不变量、兼容逻辑的代码必须使用中文注释解释原因。  


# 44. Cocos 编码规范

## 44.1 Component 只做适配

推荐：

```ts
@ccclass('RoomView')
export class RoomView extends Component {
  bind(snapshot: RoomSnapshot): void {
    // 刷新表现
  }

  playDamage(): void {
    // 播放表现
  }
}
```

不推荐：

```ts
update(dt: number): void {
  // 在这里计算真正的房间伤害
}
```

## 44.2 全局服务

通过明确的 AppContext/DI 管理，避免无约束 Service Locator。

## 44.3 事件订阅

`onEnable` 注册，对应 `onDisable` 注销。

## 44.4 巨型 Controller

一个 Component 超过约 500～800 行时应评估拆分。

## 44.5 编辑器脚本与中文 Inspector

- TypeScript 类名、属性名、文件名保持英文，保证序列化稳定并符合代码命名规范；Prefab/Scene 文件名和稳定业务 ID 同样保持英文。Prototype 标准骨架新创建的 Node 使用中文语义名，运行时查找必须保留旧英文别名，已有英文场景不自动改名。
- 所有设计人员可调的 `@property` 必须提供中文 `displayName` 和中文 `tooltip`；同一职责有多个字段时使用中文 `group`。
- Component 使用中文 `@menu` 路径，方便在“添加组件”中查找；不得为了中文显示而随意修改已经序列化的 `@ccclass` 名称。
- 视觉组件需要 `@executeInEditMode` 时，只执行绘制、尺寸刷新、锚点辅助和吸附等轻量表现逻辑。
- Inspector 属性变化后应立即刷新编辑器预览；不能要求设计人员运行游戏才能确认颜色、尺寸或布局。
- 网格吸附优先监听 Cocos `Node.EventType.TRANSFORM_CHANGED`，并在 `onDisable` 对应注销；禁止用 GameCore 或存档数据保存编辑器世界像素坐标。

推荐：

```ts
const { ccclass, executeInEditMode, menu, property } = _decorator;

@ccclass('RoomView')
@executeInEditMode
@menu('星舰协议/场景表现/房间视图')
export class RoomView extends Component {
  @property({
    displayName: '预览透明度',
    tooltip: '只影响 Prefab 编辑器中的表现，不改变房间规则。',
    group: '编辑器预览',
    min: 0,
    max: 1,
    step: 0.05,
  })
  public previewOpacity = 1;
}
```

## 44.6 Cocos 编辑器扩展代码

- 项目扩展使用独立 TypeScript 配置编译到 `dist/`，运行时代码禁止导入 `extensions/`。
- 只使用 Cocos Creator 3.8 文档标记的公开 `Editor.Panel`、`Editor.Message`、Asset DB 和 Scene 消息。
- Cocos 3.8.8 没有稳定公开层级右键注册入口；场景对象统一由可停靠 Panel 通过公开 Selection、Scene Message 创建。禁止 `src/hierarchy/`、`cce.*`、DOM 注入和私有菜单补丁；选择轮询只在面板显示期间运行，隐藏/关闭时必须注销定时器。
- Panel 优先使用原生 HTML/Cocos UI 元素；当前表单不引入 Vue、React 或重型校验依赖。
- 资源路径、稳定 ID 和数值属于信任边界，写入前必须校验；多资源写入必须处理部分失败与回滚失败。
- 共用代码只包含真实复用的菜单聚合与 Asset DB 事务；不得提前建立 NPC、关卡空实现或万能实体工厂。
- 扩展控制台消息使用 `[星舰协议]` 前缀和中文可执行说明，不输出无上下文异常。

## 44.7 原生启动器与发布安全代码

- Windows 启动器优先使用 WinHTTP、WinTrust、BCrypt、Crypt32 和标准 C++，不引入额外网络或密码运行库。
- 所有 URL 必须来自编译配置或已验签清单，并强制 HTTPS；相对文件路径必须拒绝绝对路径、盘符、空段和 `..`。
- 签名验证、Hash 校验和版本比较失败必须 fail closed，不能捕获后继续在线启动。
- 只允许网络不可达时使用本机已验签清单冷启动；服务端 HTTP 明确拒绝不是离线条件。
- 私钥、AES 密钥、HMAC Secret、代码签名证书禁止写入源码、命令输出、测试夹具或仓库。
- 发布工具的输出默认不得覆盖已有文件；正式 staging 目录必须是可丢弃、可重建的精确目录。
- Cocos 脚本加密属于混淆层；注释和文档不得把它描述成服务端反作弊替代品。

# 45. TypeScript 兼容约束

考虑 Cocos Creator 3.8 的 TypeScript/模块解析限制：

- 不使用 `const enum`；
- 类型重导出优先 `export type`；
- 使用标准 ESM；
- 避免依赖 Node API 的 npm 包；
- 客户端库必须验证 Web + Native 兼容性；
- 不使用 DOM 依赖作为 GameCore 依赖。

## 中文注释统一规范

### 核心原则

中文注释用于说明：

- 设计原因；
- 业务不变量；
- 数据兼容性；
- 确定性要求；
- 算法关键步骤；
- 缓存何时失效；
- 跨层边界为何存在；
- 性能优化为什么安全。

不要把代码逐字翻译成中文。

### 推荐示例

```ts
/**
 * 计算房间放置是否合法。
 *
 * 这里使用逻辑网格而不是 Cocos 世界坐标，
 * 目的是保证客户端显示缩放不会影响存档、AI 和服务端校验。
 */
export function validateRoomPlacement(...) {
  // ...
}
```

### TODO 格式

```ts
// TODO(R2): 联网阶段改为服务端返回配置版本；R1 暂时读取本地配置。
```

禁止：

```ts
// TODO: 以后优化
```

因为它没有说明阶段、原因和完成条件。

## Controller / Service 命名限制

- `Controller`：负责一个明确 UI/应用用例，不承担跨域规则。
- `Service`：提供跨页面或跨组件的稳定能力。
- `Manager`：慎用；新增前必须证明它确实管理生命周期或资源集合。
- `Utils` / `Helper`：尽量避免；优先使用有业务语义的名字。
