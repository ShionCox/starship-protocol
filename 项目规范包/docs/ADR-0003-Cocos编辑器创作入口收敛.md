# ADR-0003：Cocos 编辑器创作入口收敛

- 状态：接受
- 日期：2026-08-10
- 影响范围：Cocos 编辑器扩展、场景创作、房间实例、Prefab/JSON 资源工作流

## 背景

ADR-0001 已确定单一项目插件、Prefab 表现源和 JSON 规则源，但此前尝试通过 Cocos 层级管理器私有接口注入右键菜单。Creator 3.8.8 没有稳定公开的第三方层级右键注册消息，私有入口会随编辑器版本或工作区状态失效，也无法由自动测试证明菜单和撤销行为。

## 候选方案

### 方案 A：继续维护层级私有右键适配器

优点：操作位置接近层级管理器。

缺点：依赖未公开 API，版本脆弱；需要保留降级入口和两套交互路径；无法保证扩展关闭后状态清理。

### 方案 B：资源右键 + 唯一可停靠创作面板

优点：资源菜单和 `Editor.Panel` 是公开扩展点；面板可同时展示选择、校验、目录和操作状态；场景修改统一走公开 Scene 消息。

缺点：设计人员需要从面板执行场景创建，而不是直接在层级右键执行。

## 决策

选择方案 B：

- 资源管理器右键只创建房间定义 JSON 与表现 Prefab。
- 项目菜单和 Panel 菜单只打开可停靠“星舰创作工具”。
- 场景骨架、房间目录、房间实例和创作校验全部在面板内完成。
- 面板在显示期间每 500ms 读取公开 `Editor.Selection`；隐藏或关闭时停止轮询。
- 执行操作前重新查询选择和场景；成功操作只产生一次公开 Scene 快照，失败回滚并调用 `snapshot-abort`。
- 标准场景骨架新建节点使用中文语义名；运行时和插件按语义别名兼容旧英文节点，已有英文场景不自动改名。
- 禁止私有 hierarchy API、`cce.*`、DOM 注入和第二套场景编辑器。

## 原因

该方案把扩展入口限制在 Cocos 3.8 的公开 Panel、Selection、Message、Asset DB 和 Scene API，避免将版本锁定的编辑器内部 UI 当成项目契约。层级管理器仍然是设计和选择场景的地方，但不再承担第三方菜单注入职责。资源、规则、表现和场景实例的事实源保持清晰，插件关闭时运行时不需要加载任何扩展代码。

## 影响

- 代码：删除 `src/hierarchy/` 私有适配器；房间场景创建迁移到 `room-scene-authoring`，房间目录迁移到可停靠 `authoring-panel`。
- 数据：Prefab 与房间 JSON 格式不变，仍由 Asset DB 真实依赖自动发现。
- Replay：不改变 GameCore、Command、Snapshot 和整数逻辑坐标边界。
- 性能：面板只在可见期间轮询选择，选择未变化时不重复扫描场景。
- 部署：扩展仍不进入 Web/Native 运行时构建；关闭扩展不影响场景运行、存档和构建。
- Cocos 编辑器搭建与 Inspector：面板创建标准节点和 Prefab 实例，公开 Scene 消息负责属性、保存和一次 Undo/Redo 快照；中文 Inspector 和编辑器吸附规则保持不变。

## 迁移方案

1. 将 `room-catalog` 面板迁移为 `authoring` 可停靠面板，并把项目/Panel 菜单收敛为打开面板。
2. 删除层级私有适配器、菜单生成函数、旧消息和旧测试；清理 `dist/` 后重新编译。
3. 保留 `resolveRoomRoot`、GameCore 空位校验、唯一实例 ID、Prefab 绑定和失败回滚。
4. 更新 AGENTS、唯一主文档、R0-CHECKLIST 和证据；人工 Cocos 菜单、面板停靠、Undo/Redo 和关闭插件回归取得截图前不勾选新增验收项。
