# 47. 测试架构

## 47.1 GameCore 单元测试

必须覆盖：网格、放置、能源、伤害、护盾、武器、AI、路径、状态效果、胜负、RNG、Replay。

## 47.2 Determinism Test

```text
同一 InitialState
同一 Seed
同一 Commands
运行 100 次
FinalHash 必须完全一致
```

## 47.3 Fuzz Test

自动生成随机房间、随机船员、随机 AI、随机战斗，连续运行大量场次，检查 NaN、死循环、不可达路径、负 HP、负资源、超最大值、战斗无法结束。

## 47.4 Cocos 编辑器验收

涉及 Scene、Prefab、UI 或表现参数的功能必须同时验证：

- 不运行游戏即可在场景编辑器或 Prefab 编辑器看到代表性结果；
- 关键 Component 已持久挂载，场景层级和 Prefab 实例可直接选择和调整；
- ShipView 的 HullDefinition、子节点和场景装配引用完整，Scene/View/Prefab 没有重复规则网格；
- 设计人员可调属性具有中文名称、中文提示和合理分组，修改后预览立即更新；
- 网格化内容可在编辑器中拖动并自动吸附；保存、关闭、重开后位置一致；
- 运行时只绑定编辑器实例，不动态补正式节点、房间、船员或 UI；
- 保存一张场景层级与画面截图、一张中文 Inspector 截图，作为完成证据。

涉及项目编辑器扩展时还必须验证：

- 扩展管理器能够识别、启用和重新加载项目插件；
- 资源管理器菜单与中文表单可打开，合法输入能创建 JSON + Prefab；
- 项目菜单和 Panel 菜单打开同一个中文“星舰创作工具”，面板在隐藏/关闭时停止轮询；
- Boot/Main/Battle 骨架只补齐中文节点/组件，重名或错误父级停止并回滚，不创建一次性玩法内容；
- Hull/Room/Crew 菜单由 JSON + Prefab 真实依赖自动发现，非法定义或缺失绑定不进入可创建列表；
- 飞船实例在明确挂载点生成唯一 shipId；房间/船员只在明确 ShipView 内创建，没有作用域时不启动 Undo；
- 非法 ID、非法路径、重名和写入失败不会覆盖既有资产；
- 创建中途失败会回滚，回滚失败会报告残留资产路径；
- 新 Prefab 自动绑定定义并保存；Prefab 默认实例 ID 为空；
- 关闭插件后，场景运行、GameCore 测试和 Web Desktop 构建不受影响；
- 选择房间、船员、飞船、中文语义节点和普通节点时，只显示注册的白名单 DTO；识别顺序保持稳定。
- JSON/Prefab 新增、修改、删除或重新导入后目录自动刷新，不维护第二份清单。
- clean build 后运行插件测试；`dist` 不由 Git 跟踪。

- [ ] Launch Ticket 过期、篡改或 Build/Manifest 不匹配时 Bootstrap 被拒绝

# 52. R1 MVP 分层验收场景

当前已通过纯规则和旧 Prototype 交互证据的纵切是 A（基础房间）、B（能源）和 C（船员移动）。ADR-0004 重基线后的三场景、共享 UI、多船体和双舰隔离必须重新完成 Creator/Web 验收，不能复用旧 Prototype 截图宣称完成。

## 场景 A：飞船建造

玩家能够添加反应堆、激光室、护盾、医疗室、电梯，并保存布局。

## 场景 B：能源

能源不足时，激光和护盾不能同时满功率，玩家必须取舍。

## 场景 C：船员

船员可以从反应堆经过电梯移动到激光室；房间岗位数值加成尚未实现。

## 场景 D：维修

```text
激光室被击中
→ HP下降
→ AI判断
→ 工程船员移动
→ 维修
→ HP恢复
```

## 场景 E：医疗

```text
船员低 HP
→ AI判断
→ 去医疗室
→ 恢复
→ 返回岗位
```

## 场景 F：武器

```text
加电
→ 装填
→ AI选目标
→ 开火
→ 敌方护盾/房间受伤
```

## 场景 G：完整战斗

直到其中一方满足失败条件。

## 场景 H：Replay

同一 Seed + Command 重放，结果一致。

场景 A～H 全部通过后，才能进入 R2 联网。当前未完成 D～H。

# 55. Definition of Done

任何核心功能必须满足：

1. 功能实现；
2. TypeScript 无严重错误；
3. GameCore 与 Cocos 边界正确；
4. 有单元测试；
5. 有错误处理；
6. 不产生明显持续内存泄漏；
7. Web Desktop 可运行；
8. 不破坏确定性；
9. 配置有稳定 ID；
10. 文档更新；
11. 调试工具可观察；
12. 必要时升级版本号；
13. Scene/Prefab/视觉内容可在 Cocos 编辑器中直接搭建和预览；
14. 设计参数具有中文 Inspector 名称、提示和分组；
15. 网格化内容具备编辑器拖动吸附，并有持久截图证据。
16. 编辑器扩展只使用公开 API，具有自动测试、失败回滚和禁用插件回归证据。
17. 只有实际进入 R2 正式发行时，才要求签名清单、AES-GCM、原生启动器、服务端拒绝、生产证书和部署证据；当前 R1 不适用且不得伪造完成。
