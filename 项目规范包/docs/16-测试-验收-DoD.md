# 47. 测试架构

## 47.1 GameCore 单元测试

必须覆盖：网格、放置、能源、伤害、护盾、武器、AI、路径、状态效果、胜负、RNG、Replay。

## 47.2 Determinism Test

```text
同一 InitialState
同一 Seed
同一 Commands
运行 100 次
FinalHash 必须完全一致
```

## 47.3 Fuzz Test

自动生成随机房间、随机船员、随机 AI、随机战斗，连续运行大量场次，检查 NaN、死循环、不可达路径、负 HP、负资源、超最大值、战斗无法结束。

## 47.4 Cocos 编辑器验收

涉及 Scene、Prefab、UI 或表现参数的功能必须同时验证：

- 不运行游戏即可在场景编辑器或 Prefab 编辑器看到代表性结果；
- 关键 Component 已持久挂载，场景层级和 Prefab 实例可直接选择和调整；
- AppRoot 只有一个 SceneSettings，场景级网格参数集中在该组件，GridRoot/View/Prefab 没有重复配置；
- 设计人员可调属性具有中文名称、中文提示和合理分组，修改后预览立即更新；
- 网格化内容可在编辑器中拖动并自动吸附；保存、关闭、重开后位置一致；
- 运行时复用编辑器实例，不产生重复节点；
- 保存一张场景层级与画面截图、一张中文 Inspector 截图，作为完成证据。

涉及项目编辑器扩展时还必须验证：

- 扩展管理器能够识别、启用和重新加载项目插件；
- 资源管理器菜单与中文表单可打开，合法输入能创建 JSON + Prefab；
- 项目菜单和 Panel 菜单可打开中文可停靠“星舰创作工具”，面板显示当前层级选择并在隐藏/关闭时停止轮询；层级管理器不注册私有右键扩展；
- “初始化 Prototype 场景骨架”只补齐缺失节点/组件，重名或错误父级会停止并回滚；
- 新建标准骨架的层级节点必须显示中文语义名（主相机、画布、世界根、飞船根、网格根、房间容器、预览根、界面根、应用根）；旧英文场景可被兼容读取且不自动改名；
- 房间菜单由 JSON + Prefab 真实依赖自动发现，缺失绑定、多重绑定、非法 JSON 不出现在创建列表；
- 房间实例创建按语义父节点路由、生成唯一实例 ID、使用 GameCore 首个合法空位，并在网格已满时不残留临时节点；
- 非法 ID、非法路径、重名和写入失败不会覆盖既有资产；
- 创建中途失败会回滚，回滚失败会报告残留资产路径；
- 新 Prefab 创建后自动绑定定义并保存，之后可在 Prefab 编辑器预览，定义尺寸变化会刷新；
- 关闭插件后，场景运行、GameCore 测试和 Web Desktop 构建不受影响；
- 保存资源菜单、表单、创建结果、绑定后 Prefab 预览、可停靠创作面板、场景骨架和一次 Undo/Redo 截图。
- 依次选择房间实例、AppRoot、中文/英文标准骨架节点和普通节点时，创作工具能在 500ms 内显示对应白名单属性；房间实例自动切到“房间建筑”，AppRoot 自动切到“场景”。
- 房间实例的实例 ID、定义 ID、逻辑格位置和校验状态只读；共享 JSON 定义字段可编辑，定义缺失时仍显示实例信息和中文错误。
- AppRoot 的网格列数、行数、格子尺寸、自动吸附、最小/最大缩放和缩放步长可通过公开 Scene API 保存；无效参数拒绝写入，失败回滚，成功只生成一次 Undo 快照，Undo/Redo 后 Inspector 与面板一致。
- 相同 UUID 的强制刷新不抢走手动分页或资源选择；新建房间被 Creator 选中后立即联动到实例属性。
- 房间 JSON/Prefab 新增、修改、删除或重新导入后，面板无需点击刷新即可更新项目级房间目录；切换 Scene 后目录保持一致。
- 完整标准骨架中的创建仍使用 RoomRoot、首个合法逻辑格和重叠校验；无骨架但有 Canvas 时创建到 Canvas 顶层，无 Canvas 时创建到场景根节点，并显示放置模式。
- 房间目录刷新、场景放置和跨场景切换不写入第二份场景清单；目录变化不抢分页、不重置仍存在的资源选择。

# 50.A R2 Windows 正式发行安全验收

- [ ] Cocos Creator 3.8.8 Windows Native Release 构建可安装、可启动
- [ ] 启动器、游戏 EXE、DLL 和安装器 Authenticode 有效
- [ ] Cocos Native 正式脚本已加密，调试/source map 未进入发行包
- [ ] 源 JSON 不再是正式运行时配置依赖；AES-256-GCM 规则包解密和认证标签校验通过
- [ ] RSA-PSS 签名清单有效；伪造签名、错误公钥和修改 payload 均被拒绝
- [ ] 路径穿越、缺文件、多文件、大小变化、CORE Hash 变化均禁止启动
- [ ] BULK 缓存仅在同一签名 Build、大小、时间和期望 Hash 一致时复用
- [ ] 服务端返回非支持版本时禁止离线绕过
- [ ] 断网且存在已验签缓存时只进入离线/连接页；无缓存时不启动游戏
- [ ] Launch Ticket 过期、篡改或 Build/Manifest 不匹配时 Bootstrap 被拒绝
- [ ] Secret/KMS、TLS、Redis Rate Limit、审计日志和密钥轮换已在部署环境验证
- [ ] 修改客户端数据不能直接改变服务端账号、库存、奖励或战斗结果
- [ ] 签名安装器全新安装、篡改拒绝、卸载重装流程有持久截图/日志证据

自动测试和本机编译只能作为实现证据；生产证书、部署环境和最终签名安装器未实测时不得勾选正式发行完成。

# 52. R1 MVP 验收场景

## 场景 A：飞船建造

玩家能够添加反应堆、激光室、护盾、医疗室、电梯，并保存布局。

## 场景 B：能源

能源不足时，激光和护盾不能同时满功率，玩家必须取舍。

## 场景 C：船员

船员可以从反应堆经过电梯移动到激光室，并正确更新房间加成。

## 场景 D：维修

```text
激光室被击中
→ HP下降
→ AI判断
→ 工程船员移动
→ 维修
→ HP恢复
```

## 场景 E：医疗

```text
船员低 HP
→ AI判断
→ 去医疗室
→ 恢复
→ 返回岗位
```

## 场景 F：武器

```text
加电
→ 装填
→ AI选目标
→ 开火
→ 敌方护盾/房间受伤
```

## 场景 G：完整战斗

直到其中一方满足失败条件。

## 场景 H：Replay

同一 Seed + Command 重放，结果一致。

通过以上场景，才能进入 R2 联网。

# 55. Definition of Done

任何核心功能必须满足：

1. 功能实现；
2. TypeScript 无严重错误；
3. GameCore 与 Cocos 边界正确；
4. 有单元测试；
5. 有错误处理；
6. 不产生明显持续内存泄漏；
7. Web Desktop 可运行；
8. 不破坏确定性；
9. 配置有稳定 ID；
10. 文档更新；
11. 调试工具可观察；
12. 必要时升级版本号；
13. Scene/Prefab/视觉内容可在 Cocos 编辑器中直接搭建和预览；
14. 设计参数具有中文 Inspector 名称、提示和分组；
15. 网格化内容具备编辑器拖动吸附，并有持久截图证据。
16. 编辑器扩展只使用公开 API，具有自动测试、失败回滚和禁用插件回归证据。
17. 正式 Windows 发行改动通过签名清单、AES-GCM、原生启动器、服务端拒绝和篡改测试；生产证书与部署证据齐全。
