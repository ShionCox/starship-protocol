# 14. 船内寻路需求

这是项目核心技术模块之一。

## 14.1 导航图

不要直接在连续坐标中寻路，将飞船转换成导航图：

```text
房间站位
↕
房间出口
↔
相邻房间
↕
电梯
↔
特殊连接
```

## FR-NAV-001 路径搜索

建议 A*。P0。

## FR-NAV-002 路径缓存

布局没有变化时缓存 `fromNode → toNode → Path`。P0。

## FR-NAV-003 导航图重建

房间新增/拆除、电梯改变、船体切换、特殊通路改变时重建。P0。

## FR-NAV-004 目标失效

目标房间损毁、目标人员死亡或任务取消时必须重新决策。P0。

## 14.2 R1 P8 体素多层导航图实现

- 输入固定为单个 ShipSnapshot 的房间、已完成地板、连接器实例与已解析定义；不得读取 Cocos Node、Prefab、世界像素坐标或存储 API。
- 节点类型为 `FLOOR / ROOM_STATION / CONNECTOR_STOP`。已完成地板只连接同一 `y` 上的 `x±1`；上下相邻地板和普通房间永不直接相连。
- 普通房间的站位连接到底边对应的支撑地板。任何底边支撑缺失都会让布局/导航构建失败，而不是绕过地板连接相邻房间。
- 楼梯和电梯只创建 CSV 声明的停靠口节点；每个停靠口连接指定层的左或右地板入口，连接器内部再按稳定停靠顺序连接。
- 路径使用确定性加权 Dijkstra：普通水平边使用船员 `moveTicksPerEdge`，电梯纵向边使用 CSV 的 5 Tick，楼梯纵向边使用 8 Tick；同代价候选按稳定节点 ID 决胜。
- 缓存键包含 `graphVersion/moveTicksPerEdge/fromNode/toNode`。`graphVersion` 包含排序后的房间、地板、连接器停靠口、纵向耗时和完成状态；建造、拆除或连接器变化只重建所属飞船导航图。
- P8 固定验收巡逻路线为右下 `room-laser-1` → 右上 `room-medbay-1` → 左上 `room-shield-1` → 左下 `room-reactor-1`，路线分别经过楼梯和电梯。

## 14.3 固定 Tick 与表现边界

- 普通水平边消耗船员定义中的 `moveTicksPerEdge`，连接器纵向边使用端口声明耗时；核心只通过 `advanceOneTick()` 推进，并按稳定船员实例 ID 顺序处理多名船员。
- 房间站位或普通地板终点在 Command 接受时预留，避免并发超容量；连接器停靠点只能经过，不能作为最终目的地。
- `CrewView` 根据当前节点、下一节点和 `edgeProgress` 做 0.1 秒表现插值，插值不改变核心 Tick、路径或存档结果。
- 活动路径和边内 Tick 进度属于快照；刷新可以恢复移动中状态。连接器纵向耗时来自 CSV，表现层只插值，不得让上下堆叠房间绕过连接器。

## 14.4 P8 船员行为优先级

1. 玩家显式移动、维修、治疗等 Command；
2. 工程师返回已分配工地；
3. 士兵恢复实例配置的巡逻；
4. 普通船员在当前房间内进行纯表现走动或工作动画。

- 普通船员的房间内走动使用稳定实例 ID 生成的确定性表现点，不修改逻辑站位、快照或 revision。
- 士兵巡逻路线、游标、启停状态、10 Tick 暂停和阻断导航图版本进入 schema 6 快照。玩家任务立即打断巡逻；任务结束后从下一个可达点恢复。
- 路线失效时士兵回到 `IDLE`，只有导航图版本变化后才重试，避免每 Tick 重复不可达搜索。
- 巡逻和施工分配属于可被玩家任务抢占的后台行为；已经开始的维修与医疗仍必须显式停止。

## 14.5 P8.1 表现锚点与交互边界

- 每个导航节点携带纯逻辑格锚点：地板为格中心、房间为稳定站位、连接器为井道中心和停靠层高度。锚点只供表现换算，不保存像素坐标。
- `CrewView` 必须能解析路径上的每个节点；缺少锚点时中文报错并停止本次刷新，禁止静默停住后再跳到房间中心。
- 根节点只跟随权威路径 Tween；房间内闲逛只移动船员图像子节点。移动、巡逻或任务开始时图像子节点复位，避免两层位移叠加。
