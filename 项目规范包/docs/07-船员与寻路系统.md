# 14. 船内寻路需求

这是项目核心技术模块之一。

## 14.1 导航图

不要直接在连续坐标中寻路，将飞船转换成导航图：

```text
房间站位
↕
房间出口
↔
相邻房间
↕
电梯
↔
特殊连接
```

## FR-NAV-001 路径搜索

建议 A*。P0。

## FR-NAV-002 路径缓存

布局没有变化时缓存 `fromNode → toNode → Path`。P0。

## FR-NAV-003 导航图重建

房间新增/拆除、电梯改变、船体切换、特殊通路改变时重建。P0。

## FR-NAV-004 目标失效

目标房间损毁、目标人员死亡或任务取消时必须重新决策。P0。

## 14.2 R1 单层导航图实现

- 输入固定为 `ShipLayoutSnapshot` 对应的逻辑房间放置和按房间实例 ID 映射的 `RoomDefinition`；不得读取 Cocos Node、Prefab、世界像素坐标或本地存档 API。
- 每个房间生成一个稳定出口节点和 `crewCapacity` 个站位节点；站位与本房间出口双向连接。
- 两个房间只有共享长度大于 0 的边时才连接出口；仅角点接触不连通。当前电梯仍按普通 `MOVEMENT` 房间参与单层图，并作为固定样例中的必经房间。
- 当前无依赖搜索实现使用单位边代价，启发值为 0；同代价候选按稳定节点 ID 排序，因此结果等价于确定性的 A* / Dijkstra 最短路。
- 缓存键为 `graphVersion/fromNode/toNode`。`graphVersion` 由排序后的实例 ID、逻辑位置、尺寸和站位容量组成；房间合法移动后 Bootstrap 重建 `NavigationGraph`，新实例天然使用空缓存。
- R1 固定验收路径为 `room-reactor-1 → room-elevator-1 → room-laser-1`。移动期间拒绝房间拖动；全部船员到达后恢复房间移动，成功移动后立即重建导航并原子恢复 Crew 快照，失败则回滚房间位置。

## 14.3 固定 Tick 与表现边界

- 每条导航边消耗船员定义中的 `moveTicksPerEdge`；核心只通过 `advanceOneTick()` 推进，并按稳定船员实例 ID 顺序处理多名船员。
- 到达最终目标前不占用中间房间站位；目标站位在 Command 接受时预留，避免并发超容量。
- `CrewView` 根据当前节点、下一节点和 `edgeProgress` 做 0.1 秒表现插值，插值不改变核心 Tick、路径或存档结果。
- 活动路径和边内 Tick 进度属于快照；刷新可以恢复移动中状态。跨甲板连接、电梯特殊边、队列和动态障碍留到后续阶段。
